Two ways video reacts to scroll

Scroll through both sections below. The clips are drawn live in the browser so you can see the time code; on a real site they would be your rendered MP4s or image sequences.

Scroll-scrubbed

The scrollbar is the playhead. Scroll down, the video moves forward. Scroll up, it rewinds. Stop, and it freezes.

Scroll-triggered

Each video plays on its own clock and keeps looping. Scrolling past a marker swaps to the next video.

A in code

const video = document.querySelector('video');
const track = document.querySelector('.track');

function onScroll() {
  const r = track.getBoundingClientRect();
  const p = Math.min(1, Math.max(0,
    -r.top / (r.height - innerHeight)));
  video.currentTime = p * video.duration;
}
addEventListener('scroll', onScroll, { passive: true });

Encode for smooth seeking:
ffmpeg -i in.mp4 -g 1 -an -crf 22 scrub.mp4

B in code

const clips = document.querySelectorAll('video');
const markers = [0, 0.33, 0.66];   // scroll points
let current = -1;

function onScroll() {
  const p = progress();              // same as A
  const i = markers.findLastIndex(m => p >= m);
  if (i === current) return;
  clips.forEach((v, k) => {
    v.classList.toggle('active', k === i);
    if (k === i) { v.currentTime = 0; v.play(); }
    else v.pause();
  });
  current = i;
}

Videos use muted loop playsinline; CSS opacity transition on .active gives the crossfade.

Tip: GSAP ScrollTrigger handles both patterns if you'd rather not write the scroll math yourself (scrub: true for A, onEnter / onEnterBack for B).
